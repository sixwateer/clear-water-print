# 目录结构与维护说明

## 各目录放什么

| 目录 | 用途 | 谁需要关心 |
|---|---|---|
| `00_使用指南` | 面向使用者的说明书 | 所有用户 |
| `01_文档资料` | 调研报告、方案、架构文档 | 想了解技术背景/二次开发的人 |
| `02_HTML版` | 两个网页版本 | 普通用户、前端开发者 |
| `03_Skill版` | WorkBuddy 技能包与源码 | 想集成到对话工作流的人 |
| `04_小程序版` | 微信小程序原生工程 | 小程序开发者 |
| `05_后端引擎` | FastAPI + AI 融合引擎 | 后端开发者 |
| `06_素材与示例` | 演示图、测试图、效果对比图 | 所有人（体验用） |
| `07_历史归档` | 旧版文档，仅留档，不使用 | 一般不用管 |

文件命名规律：带「_」「·」的长名字是为了让人一眼看出用途和版本，例如 `净像去水印_普通版_双击即用.html`。

## 三个版本如何保持内容一致

三个版本各自独立，改一处不会影响其他版本。改动时请注意：

- **文案/品牌名**：
  - HTML 普通版 → 文件顶部 `<script>` 里的 `CONFIG`
  - Skill 版 → `03_Skill版/watermark-remover/SKILL.md` 和 `references/usage.md`
  - 小程序版 → `app.js` 的 `globalData` 和 `pages/index/index.wxml`
- **算法参数**（迭代次数等）：
  - HTML 普通版 → `CONFIG.autoIterations`
  - Skill 版 → 脚本 `--iter` 参数
  - 小程序版 → `app.js` 的 `globalData.algo`
- **配色**：
  - HTML 普通版 → CSS 的 `:root` 变量
  - 小程序版 → `app.json` 导航栏色 + `pages/index/index.wxss`

## 如何替换成自己的内容

- **换 logo/品牌**：各版本的品牌文字位置见上表；图片 logo 用 `<image>`/`<img>` 替换对应元素。
- **换示例图**：`06_素材与示例/测试输入/demo_带水印示例图.png`（程序生成，无版权风险）。HTML 普通版的内置示例由 JS 现场绘制，改 `loadExample()` 函数。
- **加新水印模板**：进阶版支持，见 `01_文档资料/双引擎融合架构与集成文档.md`。

## 二次开发路线

1. **改界面**：优先改 HTML 普通版（单文件，改完立刻能看到效果）。
2. **改算法**：三个版本算法分别在：
   - HTML 普通版 → 文件内 `fillLaplace()` 等函数
   - Skill 版 → `scripts/remove_watermark.py`
   - 小程序版 → `utils/inpaint.js`
3. **上 AI**：接入 `05_后端引擎`，让进阶版调用 LaMA / Real-ESRGAN，处理复杂背景。
4. **发布**：小程序版按 `04_小程序版/README.md` 替换为自己的 AppID 后上传审核。

## 版本控制说明

项目根目录已初始化 Git，`.gitignore` 已排除：
- 运行产物（`output/`）、缓存（`__pycache__`）、本机测试图、旧版文档目录 `research/` 等。
- 密钥、模型权重（`.env`、`*.pth` 等）永不入库。

提交前可用 `git status` 核对纳入文件。当前提交身份如需修改，用：
```
git config user.name "你的名字"
git config user.email "你的邮箱"
```
