## Issue #1 【已修复】贴边水印修复后边缘泛白（采样污染）

**现象**：框贴图像边缘时，修复区边缘泛白/泛水印色。

**根因**：`fillLaplace` 取边界像素用 `clamp` 到图像边缘，框贴边时
clamp 后的坐标落在**框内**，把水印像素当"边界条件"参与扩散。

**方案**：`mirrorSample()` —— 采样点若落在框内，沿最近方向镜像到框外；
无法镜像（该边就是图像边界）时返回 `null`，由有效边界均色兜底。
`fillAverage` 同步改为"落回框内的采样点直接弃用 + n=0 时用角落色兜底"。

**验证**：贴底边 边差 44.9 → **6.9**，贴右下角 40.5 → **7.9**，残影 0.000。

## Issue #2 【已修复】框贴角时修复区出现异色块

**现象**：框压在图像左上角，修复后出现一块米色/暖色块，与周围白墙冲突。

**根因**：贴角时两个方向的边界采样都无效，早期实现退到"图像对角像素"
兜底，把画面另一端的深色引进来了。

**方案**：无效采样点不用对角像素，改用**有效边界均色**；若一个有效点
都没有（框占满整图），用全图抽样均色。

**验证**：左上角对照场景 "与原图均色差 355 → **38.9**"，视觉与原图基本一致。

## Issue #3 【已修复】框选贴合时残留抗锯齿白边

**现象**：框贴着文字画，文字主体消失但四周留一圈浅色痕迹。

**根因**：水印的抗锯齿边缘和投影阴影在框外 1~3px，成为扩散的边界条件被保留。

**方案**：`growRect()` 按短边 6% 自适应外扩（3~12px），把过渡带纳入修复区。

**验证**：正常框残影 0.005 → **0.000**；贴底边/贴右下角同样为 0.000，无白边。

## Issue #4 【已修复】大框修复卡顿 1.6 秒

**现象**：700×600 大框修复耗时 1582ms，页面明显卡顿。

**根因**：拉普拉斯扩散每次迭代只传播 1px，大框需要数百次迭代，且工作集为全尺寸浮点数组。

**方案**：多尺度扩散——短边 >96px 时降采样到 64px 扩散（≥300 次迭代），
再双线性放大写回。第一次实现把放大坐标写成 `(i+0.5)/f`（应为
`pad-0.5+(i+0.5)*f`），导致采样越界、整块变平色，已修正并复测。

**验证**：超大框 1582ms → **约 40ms**（约 40 倍），平滑度 1.38（无条带/平色块）。

## Issue #5 【已修复】锐化改动未修复的原图区域

**现象**：开启"轻度锐化"后整张图都被锐化，违背"保护原始细节"。

**方案**：`sharpen()` 增加 `rects` 参数，只处理修复框 + 4px 过渡带，其余像素原样复制。

**验证**：框外像素与源图逐像素一致（输出图只在修复框及过渡带内被改写）。

## Issue #6 【已修复】智能识别贴边时抛 IndexSizeError

**现象**：框贴画布边缘时，框选结束瞬间控制台报错，识别徽标不出现。

**根因**：`getImageData` 的采样矩形由原图坐标乘 `S.scale` 反算，
四舍五入后可能超出画布 1px，浏览器直接抛异常，中断 `up()` 流程。

**方案**：采样前把矩形夹紧到 `[0, canvas.width/height]`，并整段 `try/catch`，
异常时回退 `smart` 并提示"区域过小或贴边"。

**验证**：浏览器端到端用例"贴边识别不抛异常"通过。

## Issue #8 【已优化】纹理被抹平（涂抹感）

**现象**：扩散修复干净但纹理背景变平滑，木纹/皮肤质感丢失。

**试验**：对比 4 种方案——
- 整块平移：斜向纹理留矩形接缝，弃用；
- 笔画级精确掩膜：半透明文字与木纹高光特征重叠，掩膜误判后膨胀失控，弃用；
- 整框扩散：作为底图（去净、无缝）；
- 高频回注：**可行**，皮肤区域最大差 7、木纹区域最大差 4，无接缝。

**方案**：`injectTexture()` —— 从上下左右 4 个候选源块中挑"颜色最接近
且自身不含水印特征（高亮低饱和占比 ≤5%）"的一块，减模糊取高频，按
羽化权重 0.85 叠回。任一约束不满足就跳过，绝不影响去水印结果；
修复面积 >400×400 时跳过以控制耗时。

**验证**：三模式 18 项断言全绿，纹理模式仅多 10~20ms，残影仍为 0.000。

## Issue #10 【已修复】智能识别把"渐变背景"误判成"重复纹理"

**现象**：内置示例图（纯渐变 + 几个色块）框选右下角后，徽标显示
"智能识别：重复纹理"，与实际不符。

**根因**：旧实现用**一阶梯度均值**判断纹理。渐变本身就有稳定的
一阶梯度，框内再压到一个色块边缘，均值就超过阈值 → 误判。
另外旧逻辑在**框内**统计，水印笔画本身的高频也会把结果推高。

**方案**：
1. 改在**框外一圈环带**统计（框扩 35% 后减去框内），避开框内水印；
2. 改用**拉普拉斯二阶差分的中位数**，平滑渐变≈0，纹理明显>0；
   中位数还能抵抗"框边恰好压到一根强边缘"的干扰；
3. 用直方图求中位数，避免为大框分配几十万个浮点数的临时数组。

**验证**（浏览器实测）：
- 内置示例（渐变+色块）：lap 中位数 **0** → 纯色/渐变 → smart ✅
- 真实木纹照片：lap 中位数 **2** → 轻纹理 → texture ✅
- 框贴画布边缘：不抛异常，正常给出结论 ✅
