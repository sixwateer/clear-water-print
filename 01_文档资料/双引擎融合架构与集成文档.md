## 一、设计目标与原则

1. **无损优先**：能拿无水印原图（引擎A）或代数无损恢复（Alpha）时，绝不用有损的 AI 重建。
2. **永不硬失败**：单个引擎失败不中断整体，按回退链自动尝试下一引擎，最后有 OpenCV 兜底。
3. **全程可观测**：每个决策、尝试、失败、耗时都写入状态轨迹（trace），便于审计与调试。
4. **合规内建**：授权未确认是致命异常，直接终止，不进入任何引擎。
5. **可插拔**：引擎实现统一契约 `FusionEngine`，新增/替换引擎不改编排逻辑。

## 三、引擎选择逻辑

`Orchestrator.select_order(ctx)` 根据**输入条件**与**引擎可用性**动态生成本次尝试顺序：

| 条件 | 纳入的引擎 | 无损性 |
|---|---|---|
| 有 `source_url` 且引擎A可用 | ① 引擎A（source） | 无损 |
| 有图片且注册了水印模板（Alpha 可用） | ② Alpha（alpha） | 无损 |
| 有图片 | ③ 引擎B（ai） | 有损 |
| 有图片 | ④ OpenCV（opencv） | 有损 |

补充规则：

- **显式偏好**：`prefer_engine` 指定某引擎时，若它在候选链中则提到首位，其余回退顺序保留。
- **可用性过滤**：`engine.available`（依赖检测）为 False 的引擎不进入候选链。
- **去重与裁剪**：结果去重，最多 `max_attempts`（默认 4）个。
- **无候选**：既无图片也无 source_url → 抛 `InvalidInputError`。

> 例：仅上传图片（无 source_url、无模板）→ 顺序为 `['ai', 'opencv']`；
> 上传图片 + 提供 source_url + 已注册模板 → `['source', 'alpha', 'ai', 'opencv']`。

## 四、失败回退条件

回退由**引擎抛出的异常类型**驱动。只有 `RecoverableError` 子类触发回退，`FatalError` 直接终止。

| 异常码 | 含义 | 触发场景 | 是否回退 |
|---|---|---|---|
| `engine_unavailable` | 引擎依赖不满足 | 缺 torch / 服务不可达 | ✅ |
| `parse_failed` | 引擎A 解析失败 | 链接无效、平台不支持、超时 | ✅ |
| `template_mismatch` | 模板不匹配 | 未注册模板、水印经压缩缩放失配 | ✅ |
| `detection_failed` | 检测失败 | YOLO 未检出水印、置信度过低 | ✅ |
| `inpainting_failed` | 擦除失败 | LaMA / E2FGVI-HQ 推理异常 | ✅ |
| `restoration_failed` | 修复失败 | Real-ESRGAN 异常 | ✅ |
| `quality_check_failed` | 质检不通过 | 全黑/纯色、尺寸异常（strict_quality 开启时） | ✅ |
| `timeout` | 执行超时 | 引擎超时 | ✅ |
| `unauthorized` | 未授权 | 合规校验失败 | ❌ 终止 |
| `invalid_input` | 输入非法 | 无输入、参数越界 | ❌ 终止 |
| `all_engines_failed` | 全部失败 | 回退链耗尽 | ❌ 终止 |

**引擎B内部降级 vs 编排层回退**：引擎B 各步骤（检测/擦除/修复）在依赖缺失时先做**步内降级**（如 LaMA→OpenCV、ESRGAN→非锐化），并在 `meta.used_fallback` 标记；只有整步无法完成时才抛异常触发**编排层回退**。`strict=True` 可禁止步内降级，强制走真 AI 模型。

## 五、处理状态机

顶层状态（`ProcessStatus`）：

```
PENDING → SELECTING → ENGINE_A | ENGINE_ALPHA | ENGINE_B → SUCCEEDED
                          ↓ (RecoverableError)
                     FAILED_RETRY → 下一引擎
                          ↓ (全部失败)
                        FAILED
```

- 引擎B 的三个子阶段通过 `trace` 中的 `step.detection` / `step.inpainting` / `step.restoration` 记录，不单独占顶层状态。
- 每次状态变化都写入 `trace`，每条含 `ts / event / engine / level / status` 及附加字段。
- 典型 trace 事件序列：
  `select.start → select.order → engine.attempt → (step.*) → engine.success`
  或失败时：`engine.attempt → engine.failed(code=...) → engine.attempt(下一引擎) → ...`

## 六、异常处理契约

**异常层次**

```
PipelineError
├── RecoverableError（可回退）
│   ├── EngineUnavailableError   ParseFailedError   TemplateMismatchError
│   ├── DetectionError           InpaintingError    RestorationError
│   ├── QualityCheckError        TimeoutError_
└── FatalError（终止）
    ├── UnauthorizedError   InvalidInputError   AllEnginesFailedError
```

所有异常提供 `to_dict()`，统一输出 `{type, code, message, details?, trace?}`。

**统一结果 `ProcessResult`**

```json
{
  "task_id": "a1b2c3d4e5f6",
  "status": "succeeded | failed",
  "engine_used": "source | alpha | ai | opencv | null",
  "lossless": true,
  "elapsed_ms": 53.0,
  "trace": [ ... ],
  "error": null,
  "meta": { ... }
}
```

- 成功：HTTP 200，返回 PNG 二进制 + 响应头 `X-Task-Id / X-Engine-Used / X-Lossless / X-Elapsed-Ms / X-Trace`。
- 失败：HTTP 422，返回上述 JSON（含 `error`）。
- `lossless=true` 仅当引擎A或Alpha成功（源头无损 / 代数无损）。

## 七、三大核心引擎实现

### 7.1 引擎A · 源头解析（`source_engine.py`）

- 输入 `source_url`（平台分享链接），POST 到解析服务（默认 `http://127.0.0.1:8001/parse`，环境变量 `PARSE_SERVICE_URL` 可配）。
- 成功直接下载无水印原图，`lossless=true`。
- 无链接 / 服务不可达 / 解析失败 → `ParseFailedError` → 回退。
- 建议对接 parse-video-py（Python 版，FastAPI/MCP，支持小红书/抖音等 20+ 平台）。

### 7.2 反向 Alpha 混合（`reverse_alpha.py` + `alpha_engine.py`）

**数学原理**（参考 gemini-watermark-remover，MIT）

半透明水印合成满足：`observed = α·F + (1-α)·B`，已知模板前景 F 与透明度图 α，可精确反解背景：

```
B = (observed - α·F) / (1 - α)      (α < 1)
B = observed                         (α = 0 无水印区)
```

- 是代数逆运算而非生成式修复，**模板匹配即可像素级无损**（float64 中间计算 + 四舍五入，误差 ≤ 1）。
- α≥1 的完全不透明像素信息已丢失，无法恢复（保守保留 observed）。
- 模板注册中心 `TemplateRegistry` 支持纯色矩形模板与自定义 alpha 图；`match()` 做颜色一致性评分，显式指定 `template_id` 时降低门槛（用户强意图）。
- 匹配失败 → `TemplateMismatchError` → 回退。

**实测**：合成水印图反解后与原图最大像素差 1、均值 0.025（8bit 量化极限），`lossless=true`。

### 7.3 引擎B · AI 修复流水线（`ai_pipeline.py`）

三步可插拔（`DetectionStep` / `InpaintingStep` / `RestorationStep` 接口）：

| 步骤 | 实现 | 依赖 | 降级 |
|---|---|---|---|
| 检测 | YOLODetection | ultralytics | 用手动框 `ctx.rects`，无则全图 |
| 擦除 | LamaInpainting | simple-lama-inpainting + torch | OpenCV Telea |
| 修复 | RealESRGANRestoration | realesrgan | 非锐化掩膜 |

- 视频场景：将 `LamaInpainting` 替换为 E2FGVI-HQ 实现即可获得时序一致性（接口不变）。
- 每步的 `used_fallback` 汇总到 `meta.used_fallback`，全程可观测。
- 当前环境未装 AI 模型，三步均走降级路径，流水线仍可跑通（实测 ~50-90ms/张）。

## 八、API 接口

### v2（融合，推荐）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v2/engines` | 引擎状态、回退顺序、选择逻辑说明 |
| GET | `/api/v2/templates` | 已注册水印模板 |
| POST | `/api/v2/templates` | 注册纯色矩形固定水印模板 |
| POST | `/api/v2/process` | 融合处理，返回 PNG + 元数据响应头 |
| POST | `/api/v2/process/json` | 融合处理，仅返回 JSON（测试决策用） |
| GET | `/api/v2/task/{task_id}` | 查询任务状态（内存存储） |

**`/api/v2/process` 关键参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `file` | file | 原始图片 |
| `rects` | str(JSON) | 水印框，原图坐标 `[{"x":280,"y":240,"w":100,"h":35}]` |
| `source_url` | str | 分享链接（引擎A 输入） |
| `template_id` | str | 固定水印模板ID（Alpha 无损） |
| `authorized` | bool | 是否确认有权处理（false → 终止） |
| `prefer_engine` | str | `auto` / `source` / `alpha` / `ai` / `opencv` |
| `strength` / `enhance` / `face` | int/bool/bool | 处理参数 |
| `strict_quality` | bool | 严格质检开关 |

### v1（兼容保留）

`GET /api/health`、`GET /api/engines`、`POST /api/inpaint` 继续可用，前端可通过 `CONFIG.apiVersion` 在 v1/v2 间切换。

**调用示例**

```bash
# 融合处理（有授权 + 手动框）
curl -X POST http://127.0.0.1:8000/api/v2/process \
  -F "file=@photo.png" \
  -F 'rects=[{"x":280,"y":240,"w":100,"h":35}]' \
  -F "authorized=true" \
  -o result.png

# 注册固定水印模板后走无损通道
curl -X POST http://127.0.0.1:8000/api/v2/templates \
  -F "template_id=xhs_logo" -F "label=小红书水印" \
  -F "width=100" -F "height=35" -F "foreground=255,255,255" \
  -F "alpha=0.5" -F "anchor=bottom_right" -F "margin_x=24" -F "margin_y=24"
```

## 九、扩展指南

| 目标 | 做法 |
|---|---|
| 新增引擎 | 实现 `FusionEngine`（`kind` / `available` / `execute`），在 `engine_registry.py` 注册；失败抛 `RecoverableError` 子类 |
| 接入真实 YOLO | 在 `YOLODetection.available()` 确保 ultralytics 可导入，配置 `weights`；或实现 `DetectionStep` 注入 |
| 视频时序修复 | 实现 `InpaintingStep` 接入 E2FGVI-HQ，替换 `LamaInpainting` |
| 接入 Real-ESRGAN | 装 realesrgan，在 `RealESRGANRestoration.run()` 初始化 `RealESRGANer` 并增强 |
| 源头解析服务 | 部署 parse-video-py，设 `PARSE_SERVICE_URL`，实现其 `/parse` 返回 `image_url` |
| 自定义水印模板 | 用 `/api/v2/templates` 注册，或构造 `WatermarkTemplate`（自定义 alpha 图样）注册到 `default_registry` |
| 模板持久化 | 当前模板存内存，重启丢失；生产应落库/配置文件，在启动时批量 `register()` |
| 异步大任务 | 现有 `/task/{id}` 为内存演示；生产接 Redis/DB + 后台队列（参考 DeMark-World REST Server） |

## 十一、当前状态与升级路径

**当前可运行状态**

- 服务运行中：`http://127.0.0.1:8000`（双击 `code/start.bat` 可重启）
- AI 模型未安装 → 引擎B 三步走降级实现，引擎A 未配置解析服务 → 默认走引擎B + OpenCV 兜底
- Alpha 引擎按需注册模板后可用，能实现像素级无损

**升级顺序建议**

1. 配置 parse-video-py 解析服务 → 启用引擎A（自有内容画质零损失）
2. 注册你实际平台的水印模板 → 启用 Alpha 无损通道
3. 安装 `torch + simple-lama-inpainting`（有 RTX 5060 GPU）→ 引擎B 擦除升级为真 AI
4. 安装 `realesrgan` → 修复步骤升级为真超分
5. 视频场景接入 E2FGVI-HQ → 时序一致去水印

> 合规提醒：所有能力仅用于处理你有权处理的自有内容。引擎A 解析与模板制作请遵守平台条款。
